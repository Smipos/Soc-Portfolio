#### Сценарий
Вы — Threat Hunter, работающий в консалтинговой компании по кибербезопасности. Один из ваших клиентов недавно пострадал от атаки шифровальщика, которая привела к шифрованию нескольких рабочих станций сотрудников. Пострадавшие пользователи сообщили, что на их рабочем столе появилась записка с требованием выкупа, а также изменился фон рабочего стола.

Ваша задача — использовать SIEM Splunk, содержащий журналы событий Sysmon с одной из зашифрованных машин, чтобы извлечь как можно больше информации.

### Задание 1
Чтобы начать расследование, можете определить имя файла записки, которую оставил шифровальщик?

Ответ:

Сначала нужно понять, какие логи нам предоставили в задании.
![sc](./screens/01.png)

У нас данные из одного хранилища - revil.

За загрузку файла отвечает событие Sysmon 11. Отфильтруем логи по этому Id и посмотрим, какие поля у нас есть.
![sc](./screens/02.png)

Окей, по полям понятно, переведем в табличный вид для удобства просмотра и вытянем следующие поля:
- winlog.event_data.CreationUtcTime - когда событие возникло
- host.hostname - на каком хосте зафиксировано событие
- host.ip - ip-адрес хоста
- winlog.event_data.Image - какой процесс создал файл
- winlog.event_data.TargetFilename - какой файл был создан
- winlog.event_data.ProcessId - PID процесса, который создал файл
- winlog.event_data.User - от имени какого пользователя работал процесс
![sc](./screens/03.png)

При просмотре событий был замечен подозрительный файл `5uizv5660t-readme.txt`, который был создан процессом `facebook assistant.exe` из папки `C:\Users\Administrator\Downloads\` в `2023-09-07 16:09:59:
![sc](./screens/04.png)

### Задание 4
Теперь, когда вы определили расположение исполняемого файла ransomware, давайте копнём глубже. Для ransomware типичная тактика — нарушать работу механизмов восстановления системы. Можете определить команду, которая была использована для этой цели?

Ответ:

Так как мы уже определили ProcessId исполняемоего файла (5348), посмотрим связанные события с этим процессом: 
![sc](./screens/05.png)

Видим следующие Sysmon события:
- 1 - запуск процесса
- 5 - завершение процесса
- 7 - загрузка DLL/модуля
- 11 - создание файла
- 13 - изменение значения в реестре

Посмотрим дополнительно события запуска процессов, связанные с файлом `facebook assistant.exe`:
![sc](./screens/06.png)

Видим запуск PowerShell с закодированной командой (аргумент -e означает Encoded), кодировка Base64. 
Раскодируем команду с использованием утилиты CyberChef:
![sc](./screens/07.png)

Команда `Get-WmiObject Win32_Shadowcopy | ForEach-Object {$_.Delete();}` означает поиск всех теневых копий Windows и удаление каждой из них.
