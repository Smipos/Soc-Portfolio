# XLMRat
### Сценарий
Скомпрометированная машина была помечена из-за подозрительного сетевого трафика. Твоя задача — проанализировать PCAP-файл, чтобы определить метод атаки, выявить вредоносные payload’ы и восстановить хронологию событий.
Сфокусируйся на том, как злоумышленник получил доступ, какие инструменты или техники использовались, а также как вредоносное ПО работало после компрометации.


### Задание 1
Злоумышленник успешно выполнил команду для загрузки первой стадии вредоносного ПО. С какого URL-адреса была установлена первая часть вредоносного ПО?

Ответ:

Сначала глянем, какие адреса участвовали в обмене данными:
`Statistics -> Endpoint`
![sc](./screens/1.png)

Видно два адреса из одной сети и один из внешней.

Проверим адрес из внешней сети на VirusTotal:
![sc](./screens/2.png)

Окей, приступаем к анализу.
Загрузка ресурсов с веба обычно происходит через метод `GET`. Отфильтруем такие пакеты с запросами:
![sc](./screens/3.png)

Видим 2 пакета.
Нажимаем на первый пакет, `ПКМ -> Follow HTTP STREAM`
![sc](./screens/5.png)

Внутри видим код, который состоит:
- Из массива строк, в элементах массива примечательно то, что есть элементы типа http и ip-адреса
	- ![sc](./screens/6.png)
- Цикл, который собирает команду для выполнения, склеивая строки
- Далее видим запуск cmd.exe с дальнейшим выполнением команды в powershell. 
	- ![sc](./screens/7.png)

Хочу также провести детальный разбор команды Powewrshell:
- -NOP - запуск PS без профиля пользователя (ускорение запуска?)
- -WIND HIDDen - предположу, что полное название `WindowStyle Hidden`, то есть пользователь не должен увидеть окно консоли
- -eXeC BYPASS - `-ExecutionPolicy Bypass`, т.е. обход политики запрета PS-скриптов
- -NONI - `-NonInteractive`, запуск PS в не интерактивном режиме, т.е. без ожидания ввода пользователя 
- И далее добавляется строка OodjR, в которой находится ссылка на вредоносный файл.

Рассмотрим 2-й пакет.
В нем можно заметить кучу hex-байтов и такой код.
![sc](./screens/9.png)
![sc](./screens/10.png)
![sc](./screens/11.png)

Проанализируем детальнее, что делает код.
1) Сначала идет преобразование hex-строк в байты
2) Далее есть такая строка: \$Fu = [Reflection.Assembly]::Load($pe). После гугления стало понятно, что PowerShell загружает .NET-сборку из массива байтов прямо в оперативную память 
3) Далее видим формирование пути: `C:\Windows\Microsoft.NET\Framework\v4.0.30319\RegSvcs.exe`. RegSvcs - нормальный системный файл Windows, который относится к Microsoft .NET Framework.
	- ![sc](./screens/12.png)
4) Далее идет сброс 3-х файлов:
	- [IO.File]::WriteAllText("C:\Users\Public\Conted.ps1", $Content)
	- [IO.File]::WriteAllText("C:\Users\Public\Conted.bat", $Content)
	- [IO.File]::WriteAllText("C:\Users\Public\Conted.vbs", $Content)
5)  И завершающим этапом создается задача в планировщике: обновление Microsoft Edge с промежутком в 2 минуты.
	- ![sc](./screens/13.png)

Красные флаги собраны, но т.к. в задании сказано именно про установку вредоноса, то нам тогда нужен 2-й пакет. Внутри него виден флаг для 1-го задания.

### Задание 3
При анализе вредоносных скриптов были обнаружены два payload’а: загрузчик и вторичный исполняемый файл. Какой SHA256-хэш у исполняемого файла вредоносного ПО?

Ответ: 

Для выполнения задания нам понадобится CyberChef. Берем hex-строку и переводим в байты.

![sc](./screens/14.png)

CyberChef сообщает нам о том, что найден PE-файл. Сохраняем результат как `filename.bin`
Далее через команду `sha256sum file_name` выполняем и получаем ответ.
